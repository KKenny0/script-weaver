# 创作者工作台：可运行切片实施计划

> 后续主计划：[以场次为核心的创作者工作台](scene-creator-workbench-master.md)。本文件保留既有实施与验收历史；新计划当前进入交互原型审阅，不能将以下记录视为新计划已交付。

日期：2026-09-05。承接已认可的创作者中心方向，保留现有 daemon、CLI + skills、文档版本、Task、ChangeSet 与媒体系统。不把本计划视为整套产品已经交付。

## 产品边界

创作者操作作品、分集和当前内容，而不是学习内部契约。探索可以随时开始；接受才改变正式事实。草稿自动保存，生成失败不覆盖当前版本，下游受影响不自动重生成。原有候选审批与文档接受两道边界暂不合并。

## 1. Idea → 故事 → 分集 → 单集写作（本轮开始）

- 复用现有作品创建与 Idea 输入，开发稿默认显示故事正文和分集卡片。
- 卡片支持添加、修改标题和剧情；自动保存仍经过原有保存协调器和 revision 检查。Markdown 是同一份数据的高级入口，不建第二套存储。
- 提交前解释缺失分集、空标题/剧情和损坏地图；后台严格接受契约保持不变。
- 接受开发稿生成分集后可选择各集写作，Codex 默认动作随文档切换。
- 来源片段绑定的地图先只读展示卡片，原文入口保留映射。删除和重排暂不提供卡片操作，避免将集号当稳定身份误改下游。
- 验收：全新隔离数据目录中创建 Idea，手写两集、保存刷新、提交接受、进入第二集编辑并再次保存；空白和损坏输入不影响已接受事实。
- 自动检查：卡片往返序列化、来源映射保护、损坏输入保留、自动保存竞争、现有审批与多集流程、production build。

## 2. 在场次里与 Codex 协作

选择一场或一段直接发起任务，显式显示输入版本和修改范围；比较完整候选后接受。复用现有 Task 与 ChangeSet，先验证局部修改不会越界。验收包括拒绝、重试、并发编辑冲突和刷新恢复。到真实用户可完成一次场次修订时进行用户验收。

## 3. 同一上下文完成视觉创作

从人物、地点、道具打开事实，比较三张图片，选一张局部修改，再接受为 REF。复用现有媒体暂存/导入和版本链。替换 REF 显示具体受影响镜头，不自动重生成。验收必须包含真实图片生成及失败恢复，而非静态候选冒充供应商结果。

## 4. 尽早看到片段

将一场组织成三个镜头，查看顺序、时长和静帧预演，再回到剧本或视觉对象修改。静帧预演与生成视频明确标识；视频服务能力以实际连接验证为准，不默认任何模型可本地部署。先复用已有分镜和生成服务，成片编辑不在本切片。

## 5. 自由探索与连续性

在已跑通路径上增加可选空间视图，用来并排比较方向和素材；它是现有对象的视图而非第二套项目事实。跨集连续性提示必须能返回相关内容并说明影响。是否需要无限画布，以真实创作者任务验证，不以行业流行决定。

## 交付与验收节奏

每一切片先通过自动检查与隔离环境交互验证，再交付可用结果。外部 Codex 执行、图片服务和视频模型未实际运行的部分单独标记，不用领域测试代替真人链路。第一切片不新增 schema、CLI 或依赖；回退界面时已有 Markdown 草稿仍可读写。后续每次只展开下一切片的细节，避免预先搭建通用编排系统。

## 第二切片实施（2026-09-05）

- 剧本编辑器支持选择一场/一段，在本页填写局部修改要求；任务冻结草稿和范围，并显示输入 revision。
- 同页读取任务、并排比较原稿与完整候选、退回提案、沿用要求重试、保留待审批候选；正式接受仍在原有版本栏。
- 前后端新增可选 `edit_scope` 契约，复用任务快照 JSON，不迁移表、不新增服务。后台限制单操作和选区外文字，提交/应用/接受三道检查阻止过期候选。
- 验证：179 项 Python 测试、保存/审批/多集前端回归、production build 通过。浏览器使用上一轮隔离测试作品，选中对白（含前置 emoji，验证码点转换），经 agent-token 回传确定性测试候选，完成比较、退回、重试、保留候选与接受投影；刷新后任务和候选历史可恢复。
- 限制：没有自动场次识别/场次专用编辑器；用户选择文字定义范围。未运行真实 Codex worker，任务需要外部领取，候选提供手动刷新。真实创作质量与自动执行体验仍待用户验收，不能视为第二阶段全量通过。
